# UsefulText — Milestone 3 plan: a packaged app

_Written 2026-09-10 at the end of Milestone 2 (version 0.2.0, steps 0–5 of
`PLAN_M2.md` done, CI green on three platforms). The brief's Milestone 3 is
"a machine without Python": build, package and release the app for macOS,
Windows and Linux the way `adam-tuoa/media_downloader` v0.6.1 does, with the
OCR engine's models and native libraries inside. This file is how, in what
order, and what was found on the way._

## 0. Decisions — recommended defaults, proceeding unless Adam says otherwise

1. **Two Mac builds, Intel first.** PyInstaller bundles are per
   architecture and onnxruntime's wheels are too, so the workflow builds
   `UsefulText-macos-x64.zip` (on `macos-15-intel`, Adam's Mac) and
   `UsefulText-macos-arm64.zip` (on `macos-latest`). Adam proves the Intel
   one on his Mac; the arm64 one waits for a real Apple Silicon machine
   (the friend's, probably).
2. **Unsigned to start.** Signing and notarisation need an Apple Developer
   ID (US$99 a year). Without it Gatekeeper says the app "cannot be opened
   because the developer cannot be verified"; the release notes give the
   right-click → Open route (and the `xattr -d com.apple.quarantine`
   fallback). Revisit if that stops the friend test cold.
3. **A zip, not a dmg.** `ditto` makes a zip that preserves the bundle;
   a dmg adds tooling for no gain at this size.
4. **Windows through the embeddable runtime, not PyInstaller** —
   media_downloader's lesson: Defender quarantines PyInstaller exes,
   while python.org's `pythonw.exe` is signed by the PSF. The wheels are
   pip-installed into the layout, so onnxruntime's DLLs and pythonnet (the
   pywebview bridge) arrive on their own; Inno Setup wraps it into a
   per-user installer (`UsefulText-windows-x64-setup.exe`). WebView2 is
   present on Windows 10/11 with Edge; if it is missing the app opens in a
   browser tab.
5. **Linux: PyInstaller onedir tarball** built on `ubuntu-22.04` (older
   glibc runs on more distros). WebKitGTK and PyGObject are system packages
   the tarball cannot carry; without them the app opens in a browser tab,
   which the README says.
6. **Only the three default models ship** (det small 9.9 MB, rec small
   21.2 MB, cls 0.6 MB) in `<bundle>/models`; the frozen launcher sets
   `USEFULTEXT_MODEL_DIR` to it. The rapidocr wheel carries every model it
   knows (260 MB); the other 230 MB are excluded. Proved offline: the CLI
   reads a sample page with only those three files in the model folder.
7. **A placeholder icon**, generated by `scripts/make_icon.py` (a blue
   rounded square with a page and text lines) into `packaging/icon.icns`
   and `icon.ico`, until Adam has art. It fixes the Python rocket in
   dialogs and the "Python" menu title.
8. **Releases on GitHub only**: a `v*` tag runs `release.yml`, which
   builds every platform and attaches the artefacts with
   `packaging/RELEASE_NOTES.md` plus generated notes. No PyPI, no
   self-update (media_downloader's updater is not taken). The first
   packaged release is **v0.3.0**.

## 1. What the bundle must carry

| Piece | Why | How |
|---|---|---|
| `app/static` | the built UI | `datas` in the spec (build the UI first) |
| rapidocr's `config.yaml`, `default_models.yaml` | the engine's config | package data, models excluded |
| three models | OCR | `packaging/models/` copied from the wheel at build time → `<bundle>/models` |
| onnxruntime dylibs/DLLs/so | inference | PyInstaller's onnxruntime hook (Mac/Linux); pip wheel (Windows) |
| pillow-heif's libheif | iPhone photos | the package's own `.dylibs`, found by the binary analysis |
| pymupdf's mupdf libs | PDF pages | PyInstaller's hook |
| pyspellchecker's word lists | suspect words | package data (`resources/*.json.gz`) |
| python-docx templates | Word export | PyInstaller's hook |
| pywebview's JS, pyobjc (Mac) / pythonnet (Windows) | the window | package data + the platform bridge |
| uvicorn's lazily imported modules | the server | hidden imports as in media_downloader's spec |

Not carried: torch, paddle, openvino (rapidocr's optional engines),
tkinter, pytest, the CLI's console script.

## 2. Steps

### Step 1 — the macOS build (this Mac, Intel) — done 2026-09-10

- [x] `scripts/make_icon.py` → `packaging/icon.png`, `icon.icns`
      (`iconutil`, macOS only), `icon.ico`.
- [x] `scripts/prepare_bundle.py`: copies the three models out of the
      installed rapidocr wheel into `packaging/models/` (gitignored) and
      checks `app/static/index.html` exists.
- [x] `packaging/UsefulText.spec`: onedir, windowed, `app/launcher.py` as
      the entry, datas (UI, models, rapidocr's config without its models,
      spellchecker's lists, pywebview's JS), uvicorn's lazy modules and
      the Cocoa bridge as hidden imports, torch/paddle/openvino/tkinter
      excluded; `BUNDLE` with `au.com.tuoa.usefultext`, the icon,
      `CFBundleShortVersionString` from `usefultext.__version__`,
      `LSMinimumSystemVersion` 11.0. First build failed the engine with
      "No module named cv2": OpenCV is a hard dependency of rapidocr, not
      an optional engine — it stays in (86 MB; opencv-python-headless would
      save ~40 MB, an option for later).
- [x] Launcher: `point_at_bundled_models()` sets `USEFULTEXT_MODEL_DIR` to
      `<bundle>/models` (PyInstaller) or `Lib/site-packages/models` (the
      Windows layout) unless the person set it; tested.
- [x] `scripts/smoke_bundle.py [--synthetic] [--pages DIR] -- <command…>`:
      launches the built app with a scratch data folder in server-only
      mode, then through the API chooses a library, creates a document
      from the pages, reads it, checks pages read and the Markdown and
      Word exports, quits and checks the exit. `--synthetic` makes a
      two-page PDF with PyMuPDF for CI.
- Done: 68 s build on this Mac; `dist/UsefulText.app` 337 MB, zip 150 MB;
  the real window opens and quits cleanly; the smoke test reads the six
  sample pages in 24 s (engine ready in 1.0 s) and exports both formats;
  the plist carries the name, version and icon; only our three models are
  inside. Adam's Finder run is the last check.

      pywebview's WinForms side repeating "Error while processing
      window.native.AccessibilityObject.Bounds", then "maximum recursion

      And the decision: on Windows the app opens in a browser tab by
      default (`--window` opts into the window), media_downloader's route
      there all along; idle shutdown ends the server once the tab is gone.

## 3. Risks

- **PyInstaller hooks drift**: onnxruntime and pymupdf hooks live in
  `pyinstaller-hooks-contrib`; a version bump can lose a dylib. The smoke
  test reads a real page, so a missing library fails the build, not the
  friend.
- **pyobjc under PyInstaller**: pywebview's Cocoa backend imports
  Foundation, AppKit, WebKit and Security; if a framework binding is
  missed the window falls back to the browser — the smoke test asserts the
  window was used on macOS (the log's "window closed").
- **Gatekeeper**: an unsigned, un-notarised app downloaded in a browser
  gets the quarantine attribute; the right-click → Open route works on
  macOS 14/15 but is one more thing for the friend.
- **Size**: ~300 MB unpacked (pymupdf 59, onnxruntime 74, numpy 37,
  pillow-heif 23, models 32, the rest); ~110 MB zipped. Fine for a
  download, too big to email.
